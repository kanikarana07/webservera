Web Services & AJAX

Complete notes on Web Services, UDDI, SOAP, WSDL, Web Service Architecture, AJAX and CORBA.

1. Introduction to Web Services

Definition

A Web Service is a software system that allows different applications to communicate and exchange data over a network. Web services make it possible for applications developed using different programming languages or running on different platforms to work together.

For example, an online shopping application may use one service for payment processing and another service for delivery tracking. These services can communicate with the main application through standard web technologies.

Main Characteristics of Web Services

  • They support communication between different applications.
  • They are platform independent.
  • They can exchange structured data over a network.
  • They support reusable software functionality.
  • They are commonly based on standard protocols.

Simple Example

A weather application can request current weather information from a weather web service and display the received data to its users.

2. Types and Architecture of Web Services

Web Service Architecture

Web service architecture describes how service providers and service consumers communicate with each other. A typical architecture includes a service provider, a service requester and a service registry.

Main Components

  • Service Provider: Creates and provides the web service.
  • Service Requester: Uses the web service to access required functionality or information.
  • Service Registry: Stores information about available web services.

Basic Architecture

Service Provider → Publishes Service → Service Registry

Service Requester → Finds Service → Service Registry

Service Requester → Uses Service → Service Provider

3. UDDI

Definition

UDDI stands for Universal Description, Discovery and Integration. It is a standard that helps businesses and applications publish and discover web services.

UDDI can be understood as a directory of web services. A service provider can publish information about a service, while a service requester can search for a suitable service.

Main Functions of UDDI

  • Publishing information about web services.
  • Discovering available web services.
  • Providing information about service providers.
  • Supporting integration between different applications.

Just as a business directory helps people find businesses, UDDI helps applications find information about available web services.

4. SOAP

Definition

SOAP stands for Simple Object Access Protocol. It is a messaging protocol used for exchanging structured information between applications in a network.

SOAP messages are commonly written using XML. The protocol defines a standard format for sending requests and responses between systems.

Basic Parts of a SOAP Message

  • Envelope: Defines the start and end of the message.
  • Header: Contains optional information about the message.
  • Body: Contains the main request or response data.
  • Fault: Provides information about errors.

Advantages of SOAP

  • Provides a standard message format.
  • Supports communication between different platforms.
  • Can work with different network protocols.
  • Supports structured communication between applications.

5. WSDL

Definition

WSDL stands for Web Services Description Language. It is an XML-based language used to describe the functionality of a web service.

A WSDL document provides information about what operations a web service offers, how requests should be sent and where the service can be accessed.

Information Provided by WSDL

  • Available operations of a web service.
  • Input and output messages.
  • Communication protocols.
  • Location of the web service.

WSDL can be compared to a technical guide that explains how another application can communicate with a web service.

6. Developing and Deploying Web Services

Developing a Web Service

Developing a web service involves creating software functions that can receive requests and provide responses to other applications.

Basic Development Steps

  1. Identify the functionality to be provided.
  2. Design the operations and data structure.
  3. Develop the service using suitable technologies.
  4. Test the service and its responses.
  5. Prepare documentation for service users.

Deploying a Web Service

Deployment means making the web service available on a server so that other applications can access it through a network. The service must be configured, tested and maintained after deployment.

Simple Flow

Develop Service → Test Service → Deploy on Server → Client Sends Request → Service Sends Response

7. AJAX

Definition

AJAX stands for Asynchronous JavaScript and XML. It is a web development technique used to exchange data with a server without reloading the complete web page.

AJAX helps make web applications faster and more interactive. Instead of loading the entire page again, only the required data or part of the page can be updated.

How AJAX Works

  1. The user performs an action on a web page.
  2. JavaScript sends a request to the server.
  3. The server processes the request.
  4. The server sends data back to the browser.
  5. JavaScript updates the required part of the web page.

Example

A search suggestion box can display suggestions while the user types, without reloading the complete web page.

8. Improving Web Page Performance Using AJAX

Introduction

Traditional web applications often reload the entire page when new information is required. AJAX improves the user experience by allowing only the required data to be exchanged.

Benefits

  • Reduces unnecessary page reloads.
  • Provides a faster and smoother user experience.
  • Updates specific parts of a web page.
  • Supports interactive web applications.

AJAX should be used carefully because efficient performance also depends on server speed, network connection and the amount of data being transferred.

9. Programming in AJAX

Introduction

AJAX programming uses JavaScript to communicate with a web server asynchronously. Modern JavaScript applications commonly use technologies such as the Fetch API to send and receive data.

Simple Example

fetch("data.json")
    .then(response => response.json())
    .then(data => {
        console.log(data);
    });

In this example, JavaScript requests data from a file or server. When the data is received, it can be processed and displayed on the web page.

10. CORBA

Definition

CORBA stands for Common Object Request Broker Architecture. It is a standard designed to allow software objects written in different programming languages and running on different platforms to communicate with each other.

CORBA uses an Object Request Broker, commonly called ORB, to help clients communicate with distributed objects.

Main Components

  • Client: Requests a service from an object.
  • ORB: Helps manage communication between objects.
  • Server Object: Provides the requested service.

Basic Working

Client → Object Request Broker → Server Object → Response

📌 Unit 3 Summary

Web services allow different applications to communicate and exchange information over a network. Technologies such as UDDI, SOAP and WSDL provide standards for discovering, describing and communicating with web services.

AJAX improves web applications by allowing data to be exchanged without reloading the complete page. CORBA is another important technology that supports communication between distributed software objects.
